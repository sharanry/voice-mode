# AGENTS.md — voice-mode

An iOS app that combines Audible and Kindle: you can **read** or **listen to** the same content, and your place stays **in sync** between the two modes. Read a few pages, switch to audio, then switch back, and you land on the same sentence.

## Product

### Core idea
- One library of content. Each item can be read as paginated text or played as audio.
- Audio comes from a text-to-speech API. **ElevenLabs** is the default; keep the provider behind a protocol so others (OpenAI TTS, AVSpeechSynthesizer as an offline fallback) can be added later.
- There is one shared **position** per item, and both modes read and write it. The canonical position is a text location (chunk index + character offset), never a timestamp. Audio maps timestamps to text locations using ElevenLabs character-level alignment (`/v1/text-to-speech/{voice_id}/with-timestamps`).

### Content sources
- EPUB (first-class)
- PDF (text extraction through PDFKit)
- Plain text / web articles (readability-style extraction from a URL)
- Other formats can come later. Every importer outputs the same normalized `Document` model (ordered chapters → paragraphs/text chunks).

### Share extension
- An iOS Share Extension accepts URLs, text, and files (EPUB/PDF) from Safari or any other app.
- It hands the payload to the main app through an App Group container, and the app imports the content and **opens it immediately**.

### Reading UI
- Minimal, close to the Audible/Kindle look: content first, chrome hidden until tapped.
- Themes: light, dark, and **pure black (#000000)** for OLED. Pure black is a first-class theme, not an afterthought.
- Paginated (horizontal page turns), not infinite scroll.
- While audio plays, highlight or keep visible the sentence being spoken.

### Listening UI
- Play/pause, ±15s / ±30s skip, playback speed, sleep timer (later), chapter list.
- Background audio plus lock-screen / Control Center controls (`MPNowPlayingInfoCenter`, `MPRemoteCommandCenter`).

## First draft scope (v0)
Build only this first. Don't gold-plate.
1. Import a single EPUB, PDF, or plain-text/URL into a local library.
2. **Reader:** paginated text, three themes (light/dark/pure black), adjustable font size.
3. **Voice mode:** generate audio for the current chapter through ElevenLabs, play it, and keep the reader's page in sync with playback (and the reverse: start playback from the current page).
4. Persist the position per item.

Out of scope for v0: accounts, cloud sync, store/purchasing, annotations, a voice picker UI beyond a single default voice.

## Tech stack
- **Swift 6 / SwiftUI**, iOS 18+ target. Use the Observation framework (`@Observable`), not Combine, for view models.
- **SwiftData** for the library and positions.
- Audio: `AVFoundation` (`AVAudioPlayer`/`AVPlayer`), with the audio session category `.playback`.
- EPUB parsing: start with a small in-house parser (unzip + OPF/spine + XHTML → text) or a well-maintained SPM package. Keep it behind an `Importer` protocol.
- PDF: `PDFKit`.
- Networking: `URLSession` + `async/await`. No Alamofire.
- Prefer Apple frameworks. Every SPM dependency must be justified.

### Layout
The Xcode project is generated by **XcodeGen** from `project.yml` (`brew install xcodegen`). `VoiceMode.xcodeproj` is git-ignored: edit `project.yml`, then run `xcodegen generate`. Never hand-edit the project file.
```
project.yml           # XcodeGen spec (targets, settings, SPM packages)
scripts/generate-secrets.sh  # .env → Generated/Secrets.swift (pre-build phase)
VoiceMode/
  App/                # entry point
  Model/              # Document/Chapter/ReadingPosition, SwiftData Book
  Library/            # library list, import flows, bundled sample book
  Importers/          # EPUB (ZIPFoundation), PDF (PDFKit), plain text, web page → Document
  Reader/             # themes, ReaderStyle, Paginator (TextKit 1), ReaderModel, ReaderView
  Player/             # NarrationPlayer (AVAudioPlayer, now playing), PlayerBar
  Sync/               # TextSegmenter: TTS chunking, sentence ranges, offset lookup
  TTS/                # TTSProvider, ElevenLabsProvider, on-disk TTSCache
VoiceModeTests/       # Swift Testing unit tests
```
Concurrency: Swift 6 with `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`. Pure data and parsing types are marked `nonisolated`. Heavy import work runs through `@concurrent` functions.

Pagination and rendering must share `ReaderStyle` attributes, and both use TextKit 1 (`UITextView(usingTextLayoutManager: false)`). If they drift apart, pages overflow or clip.

### TTS notes
- Chunk text by paragraph/sentence (stay well under the per-request character limits), synthesize lazily ahead of the playhead, and **cache audio + alignment on disk** keyed by (item, chunk, voice, model) so we never pay twice for the same text.
- Store the alignment data next to the audio. It drives sync.
- Never block the UI on synthesis. Show a buffering state.

## Secrets
- The ElevenLabs key lives in `.env` at the repo root (git-ignored). See `.env.example` for the variable names.
- A pre-build phase runs `scripts/generate-secrets.sh`, which writes git-ignored `Generated/Secrets.swift` from `.env`. Never hardcode keys in source, and never print or log `.env` values.
- This embeds the key in dev builds only. A shipped build must proxy TTS through a backend instead.

## Building & running
This is an iOS app, so verify changes on a **simulator** instead of only compiling. If your environment provides simulator device tools (e.g. `device_list` / `device_open` / `device_screenshot`), use them so the user can watch; otherwise use `xcrun simctl`.
1. Find an iOS simulator (`device_list`, or `xcrun simctl list devices available`).
2. Boot it (`device_open`, or `xcrun simctl boot <udid>`). Drive taps and typing with whatever CLI your device tools provide.
3. `xcodegen generate`, then build with `xcodebuild -scheme VoiceMode -destination 'platform=iOS Simulator,id=<udid>' -derivedDataPath build build`. Install `build/Build/Products/Debug-iphonesimulator/VoiceMode.app` with `xcrun simctl install <udid> …` and launch it with `xcrun simctl launch <udid> com.sharanyalburgi.voicemode`.
   To try the app without importing anything, use Library → **+** → **Add Sample Book**.
4. Take a screenshot (`device_screenshot`, or `xcrun simctl io <udid> screenshot out.png`) to check the UI (especially the pure-black theme and pagination) before you call a UI task done.
5. Close the device when finished.

If `xcrun simctl list runtimes` is empty, no iOS Simulator runtime is installed. Install one with `xcodebuild -downloadPlatform iOS` (or Xcode → Settings → Components) first.

Run tests with `xcodebuild test -scheme VoiceMode -destination 'platform=iOS Simulator,id=<udid>'`.

## Conventions
- Keep features in their folders. Views stay thin, and logic goes in `@Observable` models or plain services that you can unit-test.
- Unit-test importers, pagination math, and the text↔audio position mapping. These carry most of the product risk.
- Commit small, focused changes with descriptive messages. Branch off `main` for features.
